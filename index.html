Buenas Prácticas

Flujo de Trabajo Git & GitHub

Estructura de ramas y protocolo de Pull Requests aplicado para el desarrollo colaborativo del portal.

01

1. Ramas de Funcionalidad

Se prohíbe el push directo a main. Cada miembro crea una rama específica: feature/nombre-tarea.

git checkout -b feature/recursos
02

2. Commits Semánticos

Mensajes claros y concisos siguiendo el estándar: feat:, fix:, docs: o style:.

git commit -m "feat(filter): agregar buscador JS"
03

3. Push y Pull Request

Se publica la rama y se abre un PR en GitHub con descripción detallada de los cambios para revisión cruzada.

git push origin feature/recursos
04

4. Revisión e Integración

El líder de integración revisa el código, resuelve conflictos si existen y fusiona la rama en main.

git merge --no-ff feature/recursos

Guía Rápida SENATI

Instrucciones para el Trabajo Colaborativo en GitHub

Paso 1: Clonar y configurar tu identidad

git config --global user.name "Tu Nombre"
git config --global user.email "tu_correo@senati.pe"
git clone <URL_DEL_REPOSITORIO>
cd Tarea

Paso 2: Crear tu propia rama de trabajo

git checkout -b feature/tu-nombre-modulo

Paso 3: Realizar cambios y confirmar

git add .
git commit -m "feat: completar seccion asignada"

Paso 4: Subir tu rama a GitHub

git push origin feature/tu-nombre-modulo

Paso 5: Crear el Pull Request en GitHub

Ve a GitHub > Pestaña Pull Requests > Haz clic en New Pull Request y solicita la fusión hacia la rama principal.
