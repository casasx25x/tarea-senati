Control de Versiones

Metodologia de Trabajo Git & GitHub

Estandar de ramas, convencion de commits y revision colaborativa mediante Pull Requests.

01

1. Ramas Tematicas

Se trabaja en ramas independientes para cada modulo, manteniendo protegida la rama main.

git checkout -b feature/nombre-modulo
02

2. Commits Semanticos

Mensajes estructurados y descriptivos con prefijos convencionales: feat:, style:, fix:.

git commit -m "feat: modulo interactivo"
03

3. Publicacion Remota

Carga de la rama al repositorio central en GitHub para su posterior revision por pares.

git push origin feature/nombre-modulo
04

4. Revision y Fusion

Apertura de Pull Request, verificacion del codigo fuente y fusion limpia hacia main.

git merge --no-ff feature/nombre-modulo

Guia Tecnica SENATI

Procedimiento Colaborativo en Git & GitHub

1. Clonar el repositorio y configurar identidad

git clone https://github.com/casasx25x/tarea-senati.git
cd tarea-senati
git config user.name "Tu Nombre"
git config user.email "tu_correo@senati.pe"

2. Crear rama de trabajo individual

git checkout -b feature/tu-modulo

3. Registrar avances con commits claros

git add .
git commit -m "feat: descripcion del cambio implementado"

4. Subir la rama a GitHub

git push origin feature/tu-modulo

5. Crear la Solicitud de Integracion (Pull Request)

Ingresar a GitHub, seleccionar la rama correspondiente y abrir una solicitud hacia la rama main para revision.
